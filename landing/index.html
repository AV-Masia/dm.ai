Architecture

From ticket to
pull request.

A ticket changes state — and a factory wakes up. Clean runner. Fresh tools. Full context. The model reasons. A pull request waits for a human. Nothing to deploy. Nothing to babysit.

01
Ticket state change
ADO or Jira fires a service hook on ticket update
02
Bridge function
Azure Function triggers a workflow_dispatch
03
Clean runner
GitHub Actions installs DMTools CLI fresh per run
04
Build context
preJSAction pulls ticket, wiki, repo, knowledge base
05
LLM reasoning
Copilot CLI / Codex processes with full context
06
Publish results
postJSAction creates git branch + Pull Request
07
Human in loop
Engineer reviews and approves the generated PR
Zero persistent infrastructure. DMTools installs fresh on every CI run. No server to maintain, no agent process to babysit — just clean, repeatable, auditable automation.

Developer Experience

Jobs and agents in
plain JavaScript.

Read the ticket. Pull the page. Ask the model. Ship the result. Your engineers already speak this language.

agents/story_development.js 
// 1 — Read context from every connected system
const ticket   = await jira_get_ticket('PROJ-123');
const wikiPage  = await confluence_content_by_title('API Design Guidelines');
const openPRs   = await github_list_prs({ state: 'open' });

// 2 — Build context and ask the model
await file_write('context.md', buildContext(ticket, wikiPage, openPRs));
const result = await gemini_ai_chat({
  prompt:  `Implement the story: ${ticket.summary}`,
  context: file_read('context.md')
});

// 3 — Ship the result — branch + pull request, automated
await github_create_branch(`feature/PROJ-123`);
await github_create_pull_request({
  title:  ticket.summary,
  body:   result.explanation,
  branch: `feature/PROJ-123`
});
